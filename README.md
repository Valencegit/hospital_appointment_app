# Hospital Appointment Booking App

A Flutter mobile application for hospital appointment booking and patient management, built as part of a Bachelor of Science in Computer Science project at Metropolitan International University.

**Prepared by:** DUSENGE VALENCE (24/BCS/018/UKS)

## Overview

This app provides role-based access for patients, receptionists, doctors, scheduling officers, and administrators to manage hospital appointments, patient records, and scheduling.

## Setup

### 1. Prerequisites

- Flutter SDK (≥3.5.0)
- Dart SDK (≥3.5.0)
- Node.js 20 (for Cloud Functions)
- Firebase CLI (`npm install -g firebase-tools`)
- Google Cloud CLI (for the local administrator bootstrap)
- FlutterFire CLI (`dart pub global activate flutterfire_cli`)

### 2. Firebase Configuration

1. Create a Firebase project at [console.firebase.google.com](https://console.firebase.google.com)
2. Enable **Authentication** (Email/Password provider)
3. Enable **Cloud Firestore** (start in production mode)
4. Enable **Firebase Cloud Messaging**
5. Run in the project root:
   ```bash
   flutterfire configure
   ```
   This generates `lib/firebase_options.dart` with your project credentials.

### 3. Install Flutter dependencies

```bash
flutter pub get
```

### 4. Deploy Firestore Rules & Indexes

```bash
firebase deploy --only firestore
```

### 5. Deploy Cloud Functions

Before deploying, create `functions/.env.<project-id>` with a high-entropy
`ADMIN_SETUP_SECRET` value. This file is ignored by Git and must never be
committed. The secret is only for the initial administrator bootstrap.

```bash
cd functions
npm install
npm run build
cd ..
firebase deploy --only functions
```

### 6. Add Assets

Place font files in `assets/fonts/`:
- `Poppins-Regular.ttf`
- `Poppins-Medium.ttf`
- `Poppins-SemiBold.ttf`
- `Poppins-Bold.ttf`

Download from [Google Fonts – Poppins](https://fonts.google.com/specimen/Poppins).

### 7. Run the app

```bash
flutter run
```

## Roles

| Role | Access |
|---|---|
| `patient` | Register, view departments, book appointments, view own history, and request cancellation |
| `receptionist` | Manage the appointment queue and access patient records |
| `doctor` | Manage own department slots, view assigned appointments, and update visit outcomes |
| `scheduling_officer` | Create and manage appointment slots across departments |
| `admin` | Manage users and roles, departments, appointments, reports, and audit logs |
| `pending` | Signed-in account awaiting trusted role provisioning |

New public registrations are patients only. Role access is granted by Firebase
Auth custom claims set through Cloud Functions; changing a Firestore `role`
field alone does not grant access. Create the first administrator from a trusted
machine with `scripts/create-admin.cjs` and Application Default Credentials:

```powershell
npm install --prefix scripts
gcloud auth application-default login
$env:ADMIN_EMAIL = "admin@yourhospital.com"
$env:ADMIN_PASSWORD = "Use-a-new-unique-password"
$env:ADMIN_NAME = "Hospital Administrator"
node scripts/create-admin.cjs
```

The script uses the default Firebase project in `.firebaserc`; set
`FIREBASE_PROJECT_ID` to override it. If the Auth account already exists, first
verify that it is the intended administrator and set
`ADMIN_CONFIRM_EXISTING_EMAIL` to that same email. The script does not reset
existing account passwords. Alternatively, the `createAdminUser` callable can
be used once from a trusted setup client with its server-side secret.

The bootstrap callable locks after an administrator is created.
The admin user-management screen can create receptionist, doctor, and
scheduling-officer accounts with a staff ID and department, and send a password
setup email. It can also assign roles to existing accounts and manage account
status. Existing staff/admin users need claims provisioned through a trusted
migration before they can use staff features. Never put `ADMIN_SETUP_SECRET`
in the Flutter app. Remove or rotate it after initial setup and redeploy the
Functions.

Doctors can create and manage slots only for their assigned active department.
Scheduling officers and administrators can manage slots across departments.

## Key Technical Decisions

- **Concurrency-safe booking**: appointment creation uses a Firestore transaction in a Cloud Function to prevent overbooking (FR from SRS §3.2.4).
- **Role-based access control**: enforced at both UI level (GoRouter redirect) and backend level (Firestore Security Rules).
- **No passwords in Firestore**: Firebase Authentication handles all credential management (SRS FR-06).
- **Audit logging**: administrative actions write records to `audit_logs` collection.
