# Hospital Appointment Booking App

A Flutter mobile application for hospital appointment booking and patient management, built as part of a Bachelor of Science in Computer Science project at Metropolitan International University.

**Prepared by:** DUSENGE VALENCE (24/BCS/018/UKS)

---

## Overview

This app provides role-based access for **patients**, **staff**, and **administrators** to manage hospital appointments, patient records, and scheduling.

---

## Setup

### 1. Prerequisites

- Flutter SDK (≥3.5.0)
- Dart SDK (≥3.5.0)
- Node.js 20 (for Cloud Functions)
- Firebase CLI (`npm install -g firebase-tools`)
- FlutterFire CLI (`dart pub global activate flutterfire_cli`)

### 2. Firebase Configuration

1. Create a Firebase project at [console.firebase.google.com](https://console.firebase.google.com)
2. Enable **Authentication** (Email/Password provider)
3. Enable **Cloud Firestore** (start in production mode)
4. Enable **Firebase Cloud Messaging**
5. Run in the project root:
   ```bash
   flutterfire configure
   ```
   This generates `lib/firebase_options.dart` with your project credentials.

### 3. Install Flutter dependencies

```bash
flutter pub get
```

### 4. Deploy Firestore Rules & Indexes

```bash
firebase deploy --only firestore
```

### 5. Deploy Cloud Functions

```bash
cd functions
npm install
npm run build
cd ..
firebase deploy --only functions
```

### 6. Add Assets

Place font files in `assets/fonts/`:
- `Poppins-Regular.ttf`
- `Poppins-Medium.ttf`
- `Poppins-SemiBold.ttf`
- `Poppins-Bold.ttf`

Download from [Google Fonts – Poppins](https://fonts.google.com/specimen/Poppins).

### 7. Run the app

```bash
flutter run
```

## Roles

| Role | Access |
|---|---|
| `patient` | Register/login, view departments, book appointments, view own history, request cancellation |
| `staff` | View/manage appointments, manage slots, view patient records |
| `admin` | All above + manage users, departments, view reports & audit logs |

Staff and admin accounts are created manually via Firebase Authentication + Firestore (set `role` field in `users/{uid}`).

---

## Key Technical Decisions

- **Concurrency-safe booking**: appointment creation uses a Firestore transaction in a Cloud Function to prevent overbooking (FR from SRS §3.2.4).
- **Role-based access control**: enforced at both UI level (GoRouter redirect) and backend level (Firestore Security Rules).
- **No passwords in Firestore**: Firebase Authentication handles all credential management (SRS FR-06).
- **Audit logging**: administrative actions write records to `audit_logs` collection.
